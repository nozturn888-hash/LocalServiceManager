# Hermes Gateway control example / Hermes Gateway 控制示例

This optional, self-authored MIT example is distributed with Local Service Manager. It does not contain Hermes itself or install any Hermes package. Nothing runs merely by extracting the public package or opening the manager.

此示例为本工具自有的 MIT 代码，需用户主动选用；不包含或安装 Hermes 本体。解压公开包、打开管理器或导入配置均不会运行此脚本。

## Compatibility / 兼容范围

A compatible Windows Hermes installation must already exist. The default layout is:

```text
<InstallRoot>/
  home/
    hermes-agent/venv/Scripts/hermes.exe
    runtimes/python-3.11.15/python.exe
    gateway.pid                       # generated by Gateway, never shipped here
```

`InstallRoot` and `Action` are mandatory. There is no personal path, automatic discovery or default Start action. `PythonRuntime` may override the version-specific default using an absolute path or a path relative to InstallRoot; it must identify `python.exe` inside that installation. The Hermes launcher must actually use that exact runtime. Other packaging layouts require a reviewed adaptation.

需先单独安装兼容的 Windows Hermes。安装根目录和动作必须显式填写，没有机主目录、自动发现或默认启动。默认 Python 布局固定为 3.11.15；可通过 `PythonRuntime` 指定根目录内部的其他版本，但 Hermes 启动器必须实际使用该同一 Python。其他打包结构需另行核对适配。

The Gateway must write the expected `gateway.pid` receipt and support the `.gateway-planned-stop.json` protocol, including PID, start-time and Hermes-home scope. A standard or older Gateway without that stop-marker support is not covered; Stop will time out instead of killing it. This example does not patch or upgrade Hermes.

Gateway 必须写入兼容的官方 PID 凭据，并支持 `.gateway-planned-stop.json` 的 PID、启动时间、Hermes-home 范围校验及计划关闭协议。不支持该协议的标准版或旧版不在兼容范围内：关闭会超时失败，不会强杀。本示例不会修补或升级 Hermes。

## Explicit usage / 显式调用

The following commands are documentation examples; the package does not run them. Replace the illustrative installation directory with your own compatible installation.

以下为文档命令，不会自动执行；请将示意目录替换为自己的兼容安装目录。

```powershell
# Read-only identity status / 只读身份状态
powershell.exe -NoLogo -NoProfile -NonInteractive -File .\gateway-control.ps1 -InstallRoot "C:\Services\Hermes" -Action Status

# Explicit user-requested start / 用户显式启动
powershell.exe -NoLogo -NoProfile -NonInteractive -File .\gateway-control.ps1 -InstallRoot "C:\Services\Hermes" -Action Start

# Override the runtime only when the launcher uses it / 仅在启动器确实使用该运行时时指定
powershell.exe -NoLogo -NoProfile -NonInteractive -File .\gateway-control.ps1 -InstallRoot "C:\Services\Hermes" -PythonRuntime "home\runtimes\python-3.12.9\python.exe" -Action Status

# Stop or restart are always explicit / 关闭、重启必须显式指定
powershell.exe -NoLogo -NoProfile -NonInteractive -File .\gateway-control.ps1 -InstallRoot "C:\Services\Hermes" -Action Stop
powershell.exe -NoLogo -NoProfile -NonInteractive -File .\gateway-control.ps1 -InstallRoot "C:\Services\Hermes" -Action Restart
```

Use `ExpectedPid` and `ExpectedStartTicks` when an external controller supplies a previously verified identity. They strengthen the check; omitting them does not bypass the receipt, executable, full argument and start-time checks. No arbitrary execution-policy change or installation is required by this example; use a PowerShell environment allowed by your own Windows policy.

若外部控制器已有核验身份，可传入 `ExpectedPid` 与 `ExpectedStartTicks` 进一步约束。省略这两项仍须通过官方凭据、完整 EXE 路径、完整参数及创建时间核验。示例不修改系统执行策略；请使用本机策略允许的 PowerShell 环境。

## Control behavior and limits / 行为与边界

- Exact executable, full argv, installation scope and official receipt must agree; PID alone cannot authorize control. Multiple instances, extra arguments, mismatches or PID reuse refuse control.
- Start is a no-op when one verified Gateway already runs. New startup uses `gateway run` without `--replace`, leaving racing external instances to the Gateway's own startup guard.
- Stop holds the original OS process handle, rechecks identity, writes an atomic planned-stop marker and waits for drain. On timeout or changed identity it fails without forced termination. Restart continues only after a verified stop.
- Exit codes remain 0 for successful status/no-op/control, 1 for refused/failed control, or the Hermes launcher's exit code for a Start/Restart launch.
- Process-running status does not establish messaging-platform readiness. Interactive prompts or separate launcher windows may need adaptation.

- 必须同时匹配完整 EXE、参数、安装范围和官方凭据，不能仅凭 PID 控制；多实例、额外参数、身份不符或 PID 复用均拒绝。
- 已有核验 Gateway 时启动为无操作；新启动不使用 `--replace`，不会自动接管竞争出现的外部实例。
- 关闭固定原始系统进程句柄、再次核验、原子写入计划关闭标记并等待排空；超时或身份变化即失败，不强杀。重启仅在停止核验成功后继续。
- 成功状态、无操作或关闭返回 0，拒绝或失败返回 1；启动后的退出码沿用 Hermes 启动器。
- 进程存在不代表消息平台已经就绪；交互提示、自行弹窗的启动器可能需适配。

Unlike the private installation's controller, this public example deliberately has no forced-termination fallback after drain timeout. It keeps the identity and planned-stop safeguards, while leaving an unresponsive Gateway running.

与本机私人安装的控制器相比，本公开示例明确移除了排空超时后的精确句柄强制终止兜底。身份与计划关闭保护保留，无响应 Gateway 会保持运行。

## Manager integration / 与管理器的关系

Public GUI entries use the generic script mode. An externally started Gateway remains read-only in that mode; adding this example does not grant the GUI private-adapter adoption or verified external-stop permissions. Configure scripts manually, inspect every command and keep startup disabled until you have reviewed the binding. A generic entry also needs the actual service EXE and a unique command feature; stdio MCP remains managed by its owning client.

公开 GUI 仍使用通用脚本模式；外部启动的 Gateway 在该模式下只读。本示例不会赋予 GUI 私人适配器的外部接管或关闭能力。需手工配置脚本、实际服务 EXE 及唯一命令特征，逐项核对后再允许执行，自启默认关闭。stdio MCP 始终由所属客户端管理。

Local Codex Bridge and Image Workbench require separate private controllers/layouts and are not distributed in this release. Their former private-mode entries are rejected by the public build instead of being silently downgraded.

Local Codex Bridge 与生图工作台依赖独立私人控制器及布局，本版本不分发这两项。旧私人模式条目会被公开版明确拒绝，不会静默降级执行。

## Validation / 验证边界

This parameterized copy received PowerShell parser validation and static review only. Earlier development exercised the shared identity/lifecycle safeguards with isolated fixtures; those checks do not constitute real Hermes acceptance testing for this example. No real Hermes Gateway was started or stopped while preparing this release.

本参数化副本仅做 PowerShell 解析及静态审查。此前开发使用隔离测试进程验证过共用的身份和生命周期机制，这不构成本示例的真实 Hermes 验收。准备发布期间没有启停真实 Hermes Gateway。
